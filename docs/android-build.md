# Building & Deploying the Android App

This document covers the end-to-end build process for the Capacitor-wrapped
Android app. The web app source lives in the repo root; the native Android
project lives in `android/` (generated by `npx cap add android` and committed
to git).

## Prerequisites

1. **Node 20+** (for the web build)
2. **JDK 17+** (for Android builds)
   ```bash
   # On macOS: brew install openjdk@17
   # On Ubuntu: sudo apt install openjdk-17-jdk
   # On Windows: choco install temurin17
   ```
3. **Android SDK** (API 35 / Android 15 or newer)
   - Install via Android Studio (`https://developer.android.com/studio`)
   - Or via command line tools (`sdkmanager`)
4. **Gradle** — bundled via the Gradle wrapper, no separate install needed
5. **Java keystore** (for release signing) — see "Setting up signing" below

## First-time setup

```bash
# 1. Install web dependencies
npm install

# 2. Install Android dependencies (if not already done by `npx cap add android`)
npm install @capacitor/core @capacitor/android @capacitor/cli
npm install @capacitor/haptics @capacitor/share @capacitor/app \
            @capacitor/splash-screen capacitor-secure-storage-plugin

# 3. Sync native project with installed plugins
npx cap sync android
```

## Development workflow (live reload on device/emulator)

```bash
# Terminal 1: start Vite dev server
npm run dev:frontend

# Terminal 2: run app on connected Android device or emulator
npx cap run android --livereload
```

The Vite dev server must be reachable from the device. For a physical
device on the same Wi-Fi, find your machine's IP and set the server URL:

```bash
npx cap run android --livereload --livereload-url=http://192.168.1.42:5173
```

## Building a debug APK (no signing needed)

```bash
# Build the web app
npm run build:web

# Sync to Android
npx cap sync android

# Build debug APK (auto-signed with debug keystore)
cd android
./gradlew assembleDebug
# Output: android/app/build/outputs/apk/debug/app-debug.apk
```

Install on a connected device:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

## Building a release-signed AAB (for Play Store)

The Play Store requires a release-signed Android App Bundle (`.aab`), not an
APK. You need a Java keystore.

### 1. Generate a keystore (once)

```bash
keytool -genkey -v \
  -keystore android/app/keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias ttguide-upload \
  -storepass <YOUR_STORE_PASSWORD> \
  -keypass <YOUR_KEY_PASSWORD> \
  -dname "CN=Time Travelers Guide,O=Personal,C=US"
```

### 2. Create `keystore.properties` (gitignored)

Create `android/app/keystore.properties`:

```properties
storeFile=/absolute/path/to/keystore.jks
storePassword=<YOUR_STORE_PASSWORD>
keyAlias=ttguide-upload
keyPassword=<YOUR_KEY_PASSWORD>
```

**IMPORTANT**: `keystore.properties` and `keystore.jks` are secrets. They must
NEVER be committed. Verify `android/.gitignore` contains both.

### 3. Build the signed AAB

```bash
npm run build:web          # Build the web app
npx cap sync android       # Sync web assets to native project
cd android
./gradlew bundleRelease    # Build signed AAB
# Output: android/app/build/outputs/bundle/release/app-release.aab
```

The signing config in `android/app/build.gradle` reads `keystore.properties`
automatically when present. If absent, the release build falls back to
debug signing (NOT acceptable for Play Store).

### 4. Upload to Play Console

1. Go to `https://play.google.com/console`
2. Select your app (create if first upload)
3. **Release → Production → Create new release**
4. Upload `app-release.aab`
5. Fill in release notes, version, rollout %
6. Review and roll out

## Version management

`android/app/build.gradle` has `versionCode 1` and `versionName "1.0"`.
Bump these for each release:

```gradle
versionCode 2          // increment for every Play Store upload (must be > previous)
versionName "1.1.0"    // user-facing version string (semver recommended)
```

## App icon & splash

- **App icon**: `public/pwa-icon-192.png` and `public/pwa-icon-512.png` are
  copied into `android/app/src/main/res/mipmap-*/ic_launcher.png` (xxhdpi
  and xxxhdpi). For production-quality icons at all densities, generate
  proper adaptive icons via Android Studio's Image Asset Studio.

- **Splash screen**: `android/app/src/main/res/values/styles.xml` sets
  `windowSplashScreenBackground` to `#0a0a0a` (matching the app's dark
  theme). The Capacitor splash screen plugin is installed but not yet
  configured with a custom logo — to add one, edit
  `capacitor.config.ts`:
  ```ts
  plugins: {
    SplashScreen: {
      launchShowDuration: 1000,
      backgroundColor: '#0a0a0a',
      androidSplashResourceName: 'splash',
      showSpinner: false,
    },
  }
  ```

## App shortcuts

Three static app shortcuts are defined in
`android/app/src/main/res/xml/shortcuts.xml`:

1. **Quiz** — direct deep link to `/quiz`
2. **Search** — opens the search modal
3. **Settings** — opens the LLM API key config page

These appear in the Android long-press app icon menu.

## Permissions

The app requests:
- `INTERNET` — for the web app, LLM API calls, search
- `VIBRATE` — for haptic feedback on Quiz (correct/wrong answers)

Both are normal Android permissions and don't require runtime permission
prompts.

## Troubleshooting

### `JAVA_HOME` not set
```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)  # macOS
# or
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64  # Ubuntu
```

### Gradle build fails with "SDK location not found"
Create `android/local.properties`:
```
sdk.dir=/Users/you/Library/Android/sdk
```

### Signing fails: "Keystore was tampered with"
The `keystore.properties` file has the wrong password, or the keystore file
has been corrupted. Re-generate the keystore.

### AAB rejected by Play Console: "Signature version mismatch"
Enable both V1 and V2 signing in `build.gradle`:
```gradle
signingConfigs {
    release {
        v1SigningEnabled true
        v2SigningEnabled true
    }
}
```

## Web fallback

The app still works as a PWA at any HTTPS URL. The Android build is
optional. Both share the same codebase, so updating the web app also
updates the Android app (after rebuild + sync).
