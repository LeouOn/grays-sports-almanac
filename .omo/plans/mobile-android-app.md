# Mobile Android App — Extensive Setup Plan

> **Goal**: Ship the Time Traveler's Guide as a native Android app while keeping
> 100% code reuse with the existing web app. Build web OR Android from one
> codebase.
>
> **Status**: Planning document — not yet implemented.

---

## 1. Architecture Decision

### Recommendation: Capacitor (with PWA kept as-is)

| Approach | Code Reuse | Native APIs | Build Complexity | Verdict |
|----------|-----------|-------------|-----------------|---------|
| **Capacitor** | 100% | Full (via plugins) | Low | ✅ **RECOMMENDED** |
| React Native | 0% (full rewrite) | Full | High | ❌ Wastes 600+ entries, 478 tests |
| PWA only | 100% | Limited | None | ⚠️ Already done, limited native |
| Tauri Mobile | 100% | Full (Rust) | Medium | ⚠️ Android still experimental |
| Flutter | 0% (different language) | Full | High | ❌ Different ecosystem entirely |

**Why Capacitor:**
- Wraps the existing Vite-built web app in a native Android WebView
- `vite build` → `npx cap sync android` → Android Studio → APK/AAB
- Same React components, same TypeScript, same Tailwind, same tests
- Native plugins for SecureStorage, Haptics, Share, Camera, etc.
- The LLM spec's Flutter app uses `FlutterSecureStorage` — Capacitor's `@capacitor-community/secure-storage` is the direct equivalent
- Can ship to BOTH web (PWA) and Android (native) from the same `npm run build`

## 4. Native Plugins (matching the LLM spec)

### 4.1 Secure Storage (API keys — matches spec's FlutterSecureStorage)

```bash
npm install @capacitor-community/secure-storage
```

Create `src/lib/secure-storage.ts`:
```typescript
import { Capacitor } from '@capacitor/core';
import { SecureStoragePlugin } from '@capacitor-community/secure-storage';

// Platform-aware storage abstraction
export const secureStorage = {
  async get(key: string): Promise<string | null> {
    if (Capacitor.isNativePlatform()) {
      const { value } = await SecureStoragePlugin.get({ key });
      return value;
    }
    // Web fallback: localStorage (less secure but functional)
    return localStorage.getItem(key);
  },

  async set(key: string, value: string): Promise<void> {
    if (Capacitor.isNativePlatform()) {
      await SecureStoragePlugin.set({ key, value });
      return;
    }
    localStorage.setItem(key, value);
  },

  async remove(key: string): Promise<void> {
    if (Capacitor.isNativePlatform()) {
      await SecureStoragePlugin.remove({ key });
      return;
    }
    localStorage.removeItem(key);
  },
};
```

Update `useProviderSettings.ts` to use `secureStorage` instead of raw `localStorage`.

### 4.2 Haptics (chat message feedback)

```bash
npm install @capacitor/haptics
```

```typescript
import { Haptics, ImpactStyle } from '@capacitor/haptics';
import { Capacitor } from '@capacitor/core';

export function hapticFeedback(style: 'light' | 'medium' | 'heavy' = 'light') {
  if (!Capacitor.isNativePlatform()) return; // No-op on web
  const impact = {
    light: ImpactStyle.Light,
    medium: ImpactStyle.Medium,
    heavy: ImpactStyle.Heavy,
  }[style];
  Haptics.impact({ style: impact });
}
```

Usage in Quiz:
- `hapticFeedback('light')` on message send
- `hapticFeedback('medium')` on correct answer
- `hapticFeedback('heavy')` on wrong answer

### 4.3 Share (export content)

```bash
npm install @capacitor/share
```

```typescript
import { Share } from '@capacitor/share';
import { Capacitor } from '@capacitor/core';

export async function shareContent(title: string, text: string) {
  if (Capacitor.isNativePlatform()) {
    await Share.share({ title, text, dialogTitle: title });
  } else {
    // Web fallback: Web Share API or clipboard
    if (navigator.share) {
      await navigator.share({ title, text });
    } else {
      await navigator.clipboard.writeText(text);
    }
  }
}
```

## 5. LLM Strategy: Dual-Mode Architecture

### The Problem
- **Web/PWA**: API keys must stay server-side (security). Chat goes through Express server.
- **Android**: Can call provider APIs directly (no CORS, keys in SecureStorage).

### The Solution: Platform-aware LLM client

Create `src/lib/llm-client.ts`:
```typescript
import { Capacitor } from '@capacitor/core';

export type LLMMode = 'server-proxy' | 'client-direct';

export function getLLMMode(): LLMMode {
  // On native (Android), prefer client-direct if API keys are stored locally
  // On web, always use server-proxy (keys stay server-side)
  if (Capacitor.isNativePlatform()) {
    return 'client-direct';
  }
  return 'server-proxy';
}
```

#### Mode 1: Server-Proxy (web/PWA — current behavior)
```
Browser → /api/chat → Express server → Provider API → Response
```
- API keys in server `.env`
- Uses `@ai-sdk/react` `useChat` with `/api/chat` endpoint
- Already working ✅

#### Mode 2: Client-Direct (Android native)
```
App → Provider API directly → Response
```
- API keys in SecureStorage (user enters them in Settings)
- Uses `fetch()` directly to provider endpoints (Capacitor bypasses CORS)
- Maps to the spec's `OpenAICompatibleProvider`, `ClaudeProvider`, `GeminiProvider`

Create `src/lib/native-llm.ts`:
```typescript
import { secureStorage } from './secure-storage';

// OpenAI-compatible chat completions (openai, deepseek, openrouter, zai, minimax, ollama)
async function openAICompatibleChat(
  baseUrl: string,
  apiKey: string,
  model: string,
  messages: { role: string; content: string }[],
  temperature = 0.7
): Promise<string> {
  const response = await fetch(`${baseUrl}/chat/completions`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${apiKey}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ model, messages, temperature }),
  });
  if (!response.ok) throw mapHTTPError(response.status);
  const data = await response.json();
  return data.choices[0].message.content;
}

// Claude (Anthropic)
async function claudeChat(
  baseUrl: string,
  apiKey: string,
  model: string,
  systemPrompt: string,
  messages: { role: string; content: string }[]
): Promise<string> {
  const response = await fetch(`${baseUrl}/messages`, {
    method: 'POST',
    headers: {
      'x-api-key': apiKey,
      'anthropic-version': '2023-06-01',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model,
      max_tokens: 200,
      system: systemPrompt,
      messages,
    }),
  });
  if (!response.ok) throw mapHTTPError(response.status);
  const data = await response.json();
  return data.content.find((b: { type: string }) => b.type === 'text')?.text || '';
}

// Gemini (Google)
async function geminiChat(
  baseUrl: string,
  apiKey: string,
  model: string,
  contents: { role: string; parts: { text: string }[] }[],
  systemInstruction: { parts: { text: string }[] }
): Promise<string> {
  const url = `${baseUrl}/models/${model}:generateContent?key=${apiKey}`;
  const response = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents,
      systemInstruction,
      generationConfig: { temperature: 0.7, maxOutputTokens: 200 },
    }),
  });
  if (!response.ok) throw mapHTTPError(response.status);
  const data = await response.json();
  return data.candidates[0].content.parts
    .filter((p: { thought?: boolean }) => !p.thought)
    .map((p: { text: string }) => p.text)
    .join('');
}

function mapHTTPError(status: number): Error {
  if (status === 401 || status === 403) {
    return new Error('Authentication failed. Please check your API key.');
  }
  if (status === 429) {
    return new Error('Rate limit exceeded. Please try again later.');
  }
  return new Error(`Provider error: HTTP ${status}`);
}
```

## 6. Server Strategy

### Option A: No server on mobile (fully self-contained)
- All data is bundled (already in `src/data/*.ts` — 600+ entries compiled into the app)
- LLM calls go directly to provider APIs (Mode 2 above)
- Bookmarks/progress stored in IndexedDB (already implemented)
- No Express server needed on-device

### Option B: Remote server (for companion reactions, palace links)
- Deploy Express server to a cloud host (Railway, Fly.io, Render)
- App points to remote server URL
- Used for: `/api/athena/commentary`, `/api/companion/comment`, `/api/athena/palace-link`
- These are optional features — the app works without them

### Recommendation: Option A for MVP, Option B later
The core app (content modules, search, quiz, detail modals) works fully offline
with bundled data. The server-dependent features (companion reactions, palace
links) can be disabled on mobile or pointed to a remote server.

## 8. Offline Strategy (already strong, enhanced for mobile)

| Layer | Current (web) | Enhanced (Android) |
|-------|---------------|-------------------|
| Content data | IndexedDB knowledge cache ✅ | Same + bundled in APK |
| Bookmarks | IndexedDB + offline write queue ✅ | Same |
| Chat history | localStorage per session ✅ | Same (or SecureStorage) |
| Chat messages | Offline queue ✅ | Same |
| Static assets | Service worker cache ✅ | Bundled in APK (no SW needed) |
| LLM calls | Requires server ❌ | Direct to provider (if online) |

The app is ALREADY offline-capable for all content. The only thing that needs
connectivity is LLM chat — and with the client-direct mode, that just needs
internet access to the provider API.
